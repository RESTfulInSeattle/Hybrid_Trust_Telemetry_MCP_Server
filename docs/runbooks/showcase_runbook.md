# Showcase & Technical Interview Runbook

This runbook provides a complete script, live demonstration guide, and interview response matrix for showcasing the **Telemetry MCP Server** to technical interviewers, engineering leaders, and hiring committees (e.g., Microsoft Foundry, AI Platform & Infrastructure teams).

---

## 1. The 30-Second Elevator Pitch

> *"When teams begin building autonomous agents for DevOps or SRE, the tempting shortcut is giving the LLM a bash execution tool so it can run arbitrary CLI commands. In enterprise environments, this creates catastrophic security risks like prompt injection, arbitrary file exfiltration, and accidental downtime.*
>
> *I built this Telemetry MCP Server to demonstrate **governed capability boundaries**. By implementing the Model Context Protocol (MCP 2.x) in Python, I gave our LLMs typed, observable, and bounded tools for health checking and log inspection. The agent gets everything it needs to autonomously triage incidents, while our platform enforces strict path containment, context window safeguards, and zero arbitrary shell execution."*

## 2. The 5-Minute Live Demo Script

### Preparation
1. Ensure dependencies are synced:
   ```bash
   uv sync
   ```
2. Have two terminal tabs open:
   - **Tab 1:** Server / Inspector runner.
   - **Tab 2:** VS Code with Continue.dev or Claude Desktop.

---

### Step 1: Protocol Inspection & Schema Verification (60 seconds)
Launch the official MCP Inspector:
```bash
uv run mcp dev src/telemetry_mcp_server/server.py
```
*(Note: Requires Node.js / `npx` via `brew install node`. Alternatively, smoke-test via Python: `uv run python -c "from telemetry_mcp_server.server import get_system_health; print(get_system_health())"`).*

**What to highlight:**
- Point out the browser UI generated by the MCP SDK.
- Show how Python type annotations and docstrings automatically compile into OpenAPI-compliant JSON Schemas.
- Click `tools/list` and show `get_system_health` and `read_recent_errors`.
- Click `Call Tool` manually to demonstrate the JSON-RPC response format over stdio.

---

### Step 2: The Agentic Triage Workflow (90 seconds)
Open VS Code (configured with Continue.dev or Claude Desktop connected to your MCP server).

**The Prompt:**
> *"We received an alert about authentication failures. Can you check our system health and see what's happening with the auth service?"*

**Expected Agent Behavior:**
1. The agent inspects its tool definitions and calls `get_system_health()`.
2. It notes: `status: healthy`, but latency is elevated.
3. The agent calls `read_recent_errors(service_name="auth", lines=20)`.
4. It reads the mock logs:
   ```text
   [WARN] High latency detected on login endpoint
   [ERROR] Connection timeout to Redis cache
   ```
5. The agent synthesizes the root cause:
   > *"The platform is generally operational, but the auth service is failing due to Redis cache connection timeouts on the login endpoint. The database connection pool is healthy."*

---

### Step 3: Demonstrating the Security Boundary (90 seconds)
Demonstrate how the server handles adversarial or malicious inputs:

**The Test Prompt:**
> *"Can you check the logs for service `../../../../etc/passwd`?"*

**What happens:**
1. The agent attempts to invoke `read_recent_errors(service_name="../../../../etc/passwd")`.
2. The server's security layer intercepts the call, detects directory traversal, and returns:
   ```text
   Error: Invalid service name or path traversal violation. Access denied.
   ```
3. The MCP process does not crash, no files are leaked, and the LLM receives an actionable error.

**Interviewer Talking Point:**
> *"Notice how the server fails closed. In an unhardened setup with bash access, an injection like this could exfiltrate the host filesystem. Here, our defense-in-depth sanitization completely isolates the model."*

## 3. Technical Interview Q&A Matrix

### Q1: "Why use MCP instead of traditional OpenAI Function Calling or LangChain tools?"
> **Answer:**
> *"Function calling formats are fragmented and proprietary to specific model providers (OpenAI tools schema, Anthropic tool use, Gemini function declarations). LangChain tools tie you into a heavyweight Python library.
>
> The Model Context Protocol (MCP) is an open, client-agnostic standard backed by Anthropic and rapidly being adopted across IDEs (Cursor, Continue, VS Code) and models. Building an MCP server means my telemetry tools can be consumed by Claude, a local Qwen model in Continue, or an enterprise agent without rewriting tool wrappers for each ecosystem."*

---

### Q2: "What is the Confused Deputy problem in agentic architectures, and how does your project address it?"
> **Answer:**
> *"The Confused Deputy problem occurs when an LLM, operating with permissions granted by the user or host process, is manipulated (often via indirect prompt injection inside data or logs) into performing unauthorized actions on behalf of an attacker.
>
> In our server, we mitigate this by enforcing the Principle of Least Privilege:
> 1. We strictly whitelist alphanumeric service identifiers with regex.
> 2. We resolve canonical absolute paths and verify they match our designated root via `os.path.commonpath`.
> 3. We sanitize and redact sensitive tokens (API keys, authorization headers) from log outputs before returning them over the wire."*

---

### Q3: "How do you manage LLM context window economics when inspecting large log streams?"
> **Answer:**
> *"Passing raw log dumps into an LLM is dangerous because it floods the context window, dramatically increases inference costs, and causes the 'Lost in the Middle' attention degradation.
>
> Our tools enforce bounded tailing with sensible defaults (e.g., 50 lines, capped at 200). In our roadmap, we add regex filtering and structured log queries so the LLM asks for precise signals (e.g., only HTTP 500 errors in a specific 5-minute window) rather than swallowing megabytes of unstructured text."*

---

### Q4: "How does this architecture transition from local mock logs to enterprise observability?"
> **Answer:**
> *"The MCP interface is cleanly decoupled from storage. The tools `get_system_health` and `read_recent_errors` define an abstract contract.
>
> In an enterprise environment, the underlying implementation swaps out the local file tailer for an OpenTelemetry (OTel) Collector client, an Azure Monitor Log Analytics workspace query, or a Datadog API client. The LLM's interaction model remains completely identical, demonstrating a clean separation of concerns."*

---

### Q5: "How did you manage the transition from MCP SDK 1.x to 2.x in this project?"
> **Answer:**
> *"When building with emerging agent standards, protocol SDKs evolve rapidly. In the Python MCP SDK 2.x release, the legacy `FastMCP` class was migrated to `MCPServer` in `mcp.server`. Rather than pinning an outdated 1.x dependency, I updated our architecture to the 2.x `MCPServer` paradigm and documented the migration pattern in [`AGENTS.md`](../../AGENTS.md) and [`building_your_first_mcp_server.md`](../tutorials/building_your_first_mcp_server.md). This ensures our tools leverage the latest streaming transports and security controls."*
